# Quality Context Management

Quality context is selected progressively. Load standards-pack selection and
precedence guidance first, then only references applicable to the changed
surface. Load detailed stack material only after the selection record identifies
that stack and surface.

Pass compact rule IDs, source references, classifications, overrides, and
evidence IDs between preparation, review, and verification. Do not copy a
source catalog, vendor prose, full checklist, command log, or historical result
into a routine result. An applicable area that cannot be reviewed remains an
explicit evidence gap; retrieval volume is not coverage evidence.

Canonical quality entrypoints link here rather than restating this policy.
Repository-owned commands, SDK versions, paths, and toolchains stay in the
target repository or validated invocation configuration.

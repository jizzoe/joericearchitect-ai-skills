# Claude Cross-Tool Repository Hygiene

Date: 2026-08-18
Status: Design brief — ready for OpenSpec Propose.

## Purpose

Make repository-owned Claude and Codex guidance discoverable and keep every
canonical reusable skill adapter drift-checked. This is the low-risk,
independent successor to the archived Claude cross-tool gap inventory.

## Accepted decisions

- Add a root `CLAUDE.md` containing exactly `@AGENTS.md`. It imports the
  shared repository rules without creating a second policy surface.
- Generate adapter-drift coverage from every `skills/base/*/SKILL.md` package.
  Require matching thin `.claude/skills/<name>/SKILL.md` and
  `.agents/skills/<name>/SKILL.md` adapters, and validate their canonical
  reference and no-policy-duplication contract.
- Explicitly exclude OpenSpec-generated `.claude/skills/openspec-*`,
  `.agents/skills/openspec-*`, and `opsx` commands. They are owned and
  regenerated by OpenSpec, not by the canonical `skills/base` catalog.

## Current evidence

- No root `CLAUDE.md` exists, so Claude Code does not automatically receive
  the root `AGENTS.md` safeguards that Codex receives.
- The current hard-coded drift list covers seven of eighteen canonical skills;
  the remaining eleven lack this repository-owned parity check.
- OpenSpec-generated assets remain outside this check by deliberate ownership
  boundary, not silent omission.

## Requirements

1. A fresh Claude Code session at repository root SHALL load the same shared
   contributor guidance through the one-line import.
2. Canonical skill enumeration SHALL be deterministic and fail when a
   repository-owned Claude or Codex thin adapter is absent or violates its
   thin-adapter contract.
3. Generated OpenSpec assets SHALL be explicitly documented as excluded; the
   change SHALL NOT hand-edit them.
4. Tests SHALL cover a newly added canonical skill, a missing adapter, and a
   policy-duplicating adapter.

## Scope and non-goals

This change does not alter OpenSpec generation, Claude global settings,
authentication, independent-review isolation, or any canonical skill policy.
It adds discovery parity and validation only.

## Proposal shape

One small change: `add-claude-cross-tool-repo-hygiene`, with a root
`CLAUDE.md`, generated canonical-adapter inventory, focused tests, and docs.

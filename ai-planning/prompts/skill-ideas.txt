- GitHub Flow automation base skill candidates
  + `git-change-inspection`
    - Inspect untracked, unstaged, staged, committed, branch, and PR changes.
    - Separate user changes from generated or unrelated changes.
    - Produce a scoped change summary and verification inventory without mutating Git.
  + `git-topic-branch-management`
    - Create `feature/`, `fix/`, `hotfix/`, or `chore/` branches from current `main`.
    - Require the primary GitHub issue number and a short slug.
    - Detect uncommitted work, stale `main`, branch collisions, and incorrect base before creation.
    - Treat the branch name as human context, not the formal GitHub issue relationship.
  + `git-commit-authoring`
    - Inspect the intended staged scope, propose a meaningful commit message, and commit only approved files.
    - Verify Git identity, hooks, and resulting commit state.
    - Never stage unrelated user changes automatically.
  + `github-pr-authoring`
    - Create or update a draft PR targeting `main` from the current topic branch or fork.
    - Populate summary, `Closes #N`, OpenSpec links, verification, security, attribution, and release/deployment impact.
    - Preview all GitHub mutations before execution and report the resulting PR URL.
  + `github-pr-linkage`
    - Create, verify, or repair the formal GitHub Development relationship among issue, branch, and PR.
    - Validate the closing keyword, `main` base, primary OpenSpec change, and issue-number branch convention.
    - Do not infer linkage solely from the branch name or a plain issue mention.
  + `github-pr-readiness`
    - Review scope, checks, unresolved comments, issue/OpenSpec links, conflicts, and verification evidence.
    - Recommend whether a draft PR is ready without marking it ready or merging unless explicitly authorized.
  + `github-squash-merge`
    - Resolve and record the current PR head SHA, then perform a pre-merge audit of issue linkage, `main` base, required checks, reviews, mergeability, and accepted OpenSpec verification evidence.
    - Re-audit whenever the head SHA changes after verification or approval; never merge evidence that belongs to an older PR head.
    - Generate the final squash commit subject/body from the complete PR change.
    - Require explicit authorization immediately before merge.
    - After the merge command, independently verify the PR is merged, the closing issue is closed, the remote topic branch is deleted when required, and `main` contains the resulting squash commit.
    - Inspect Project state only when configured and authorized; do not mutate it as an implicit side effect of merge verification.
    - Treat GitHub delivery as distinct from OpenSpec spec sync and archive, and stop before either action unless separately authorized.
  + `git-topic-branch-cleanup`
    - Confirm a topic branch was merged or otherwise abandoned intentionally.
    - Check for unique commits, open PRs, worktrees, and automation references before local or remote deletion.
    - Preview deletions and require approval for any ambiguous or destructive cleanup.
  + `github-ruleset-audit`
    - Compare `main` rulesets and merge settings with the accepted GitHub Flow standard.
    - Audit PR requirement, checks, conversation resolution, force-push/deletion protection, bypasses, and merge methods.
    - Default to read-only reporting; use explicit repair mode for approved mutations.
  + `github-actions-workflow-authoring`
    - Design focused Actions workflows with explicit triggers, least-privilege permissions, concurrency, and idempotency.
    - Separate trusted mutation jobs from untrusted PR validation.
    - Pin third-party Actions by immutable SHA and provide test/dry-run behavior.
  + `github-actions-security-review`
    - Review event choice, token permissions, secrets, fork behavior, `pull_request_target`, script injection, Actions pinning, and recursion assumptions.
    - Treat workflow changes as supply-chain and credential-boundary changes.
  + `github-actions-run-diagnostics`
    - Inspect failed or skipped workflow runs, jobs, annotations, logs, event payload assumptions, and permissions.
    - Identify the root cause and propose a targeted retry or fix without weakening required checks.
  + `github-lifecycle-audit`
    - Compare issue, OpenSpec, branch, PR, Project, merge, and archive state.
    - Report drift in read-only mode and support explicit idempotent repair.
    - Verify that only a squash merge to `main` or an approved no-code completion reaches `Done`.

- Implementation boundary for Git/GitHub skills
  + Skills own reasoning, selection, review, previews, recovery guidance, and evidence reporting.
  + Deterministic Node scripts own parsing, validation, GitHub API calls, and repeatable mutations.
  + GitHub Actions own repository-event enforcement and reconciliation.
  + Destructive branch deletion, PR merge, production deployment, and release publication require explicit authorization.

- OpenSpec workflow base skill candidate
  + `openspec-action-context`
    - Resolve the selected OpenSpec change and its current Git branch, formally linked GitHub issue, pull request, Project state, and delivery status before an action runs.
    - Detect stale, conflicting, missing, or superseded relationships and stop or report them instead of relying on conversation history.
    - Translate the user's request into an explicit action boundary: permitted automatic corrections, approval-required judgment calls, prohibited mutations, and required stopping point.
    - Default to no permission for merge, issue closure, Project mutation, spec sync, archive, release, deployment, or destructive recovery unless the current request explicitly authorizes it.
    - Supply a concise context-and-authorization contract to `propose`, `apply`, `verify`, `sync`, and `archive` without duplicating those generated workflows.
    - Keep issue numbers, branch names, pull-request numbers, repository owners, Project identifiers, and credentials out of the reusable skill; resolve them dynamically or accept them through configuration.
    - Report the resolved context and boundary before mutation so the user can correct an inaccurate assumption.
